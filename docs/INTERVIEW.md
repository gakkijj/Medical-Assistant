# 面试讲解提纲

## 一分钟版本

MediX 不是简单堆叠多个 Agent。旧架构所有请求都先调用 LeadAgent，增加一次规划成本；我把复杂度判断和 Agent 意图选择拆开，设计了安全规则、语义意图和低置信度 LLM 兜底的三级路由。简单请求直达单 Agent，复杂问题才启动并行 Swarm。同时建立路由和 RAG 消融实验、请求级 Trace、Token/延迟指标、并发状态隔离、SSE、Prometheus 和 CI 回归门禁。

## 重点追问

### 为什么不用 LLM 做全部路由？

确定性安全规则延迟低、可审计，能保证急症路径稳定；语义规则覆盖常见意图；只有低置信度样本才支付 LLM 成本。这样可以量化规划率和费用，而不是笼统宣称“智能”。

### 为什么没有直接使用 LangGraph？

项目保留自研 Agent Loop，是为了展示 Tool Calling、状态、约束、记忆和并发上下文的底层实现。生产扩展时可把显式状态迁移到 LangGraph，但框架替换不应掩盖路由和评测设计。

### 为什么混合检索没有超过 BM25？

当前演示语料规模小且关键词重合高，BM25 的 MRR 更高。这个结果说明应先根据数据选择方案，而不是为了技术栈强行宣称 Dense Retrieval 更好。下一步会扩充语义改写集并接入真正的 Embedding 和 Reranker。

### 100%路由准确率可信吗？

它只表示40条透明回归用例，没有临床意义，也不能代表线上泛化。项目明确暴露数据和失败分析入口，并把扩大数据、人工双标和真实流量回放列为下一步。

### 并发安全怎么保证？

工具计数和 Trace 是请求级状态，Swarm Context 通过参数传递，不再挂到共享 Worker；会话记忆按 session ID 分桶。API 用信号量保护外部服务，而不是全局锁串行所有请求。
